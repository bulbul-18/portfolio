GitHub Knowledge Assistant

Understanding an unfamiliar codebase is slow, so I built an assistant that reads the repository and answers with the exact lines it used.

GitHub Knowledge Assistant, home screen of the live app

  1. 01

    The problem

    Understanding an unfamiliar codebase is slow, and chat assistants are a poor fit. You upload files by hand and repeat it in every chat, and pasting a whole codebase into one prompt makes answers vaguer, slower and more expensive. Nothing does the searching for you.

  2. 02

    What I built

    A full-stack app where you paste any public GitHub repository URL and ask questions in plain English. It indexes the repository once, answers each question using only the few code chunks that are actually relevant, and cites the exact files and line ranges it used.

  3. 03

    How it works

    A hand-built RAG pipeline with two stages. Indexing, once per repo: fetch the file tree from the GitHub API, filter out noise, split files into overlapping 40-line chunks, embed each with Cohere and store the vectors in PostgreSQL with pgvector. Querying, per question: embed the question, run a cosine-distance search in SQL scoped to that repo, send the top three chunks to Cohere's chat model with a prompt that restricts it to the provided code, and return the answer with file paths, line ranges and similarity scores.

  4. 04

    The hard part

    Several things broke along the way. Google's Gemini API rejected newly issued keys with 401 errors, a platform issue I traced through developer forums before migrating to Cohere. Cohere then capped requests at 96 texts and 100k tokens a minute, so I added sub-batching with retry and exponential backoff and confirmed the recovery in the logs. Windows line endings were also polluting chunk text before embedding, so I normalised them in the chunker.

  5. 05

    Status and limits

    Live and working end to end, deployed on Vercel, Render and Neon.

    The login screen is a placeholder with no real authentication, and chat history is stored per device in the browser. Retrieval is sensitive to wording, and broad questions such as "what is this project for?" are weaker. Next on the list: real authentication, README-aware context, background indexing and syntax-aware chunking.

The backend runs on a free tier, so the first request can take around 50 seconds to wake up.
