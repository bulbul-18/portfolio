LoopBack, landing page of the live app

  1. 01

    The problem

    While preparing for interviews, I kept solving a LeetCode problem, moving on, and meeting a similar one weeks later that felt brand new. I was counting solves, not retaining techniques. Flashcard tools do not know how you solved something (cold, with a hint, or from the solution), and that changes how long it sticks.

  2. 02

    What I built

    A multi-user web app that syncs accepted LeetCode submissions, has you tag how you solved each one, and schedules when to re-solve it from memory. Problems recalled cleanly several times graduate to a searchable archive, so the queue never grows forever.

  3. 03

    My role

    Solo personal project. I designed, built and deployed it: data model, authentication, the LeetCode integration and hosting.

  4. 04

    The hard part

    "Today" was computed in server time, so problems appeared a day early or late. I fixed it by sending the browser's local date with each request. I also made the sync safe to retry: the timestamp advances only after a full batch succeeds, and duplicate inserts are ignored at the database level.

  5. 05

    Outcome

    Live and working end-to-end for email accounts, deployed on Render with a Neon PostgreSQL database and auto-deploy from GitHub.

    Google sign-in and password-reset emails are built but not enabled in production.
